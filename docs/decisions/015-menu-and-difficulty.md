# 決定 015: スタートメニューと、難易度(3段階)を作る

- 日付: 2026-11-03
- 決めた人: 開発者(依頼)と、Claude(作り方の案)。仕様書は `docs/specs/015-menu-and-difficulty.md`。
- 関連: 天敵側(農家さんをプレイする遊び方)は、仕様書 016。この決定では「`Farmer` を選べる土台」までを作った。

## 依頼
- 「難易度選択をしたい。難しければいらない」(開発者)。
- 「天敵側をやるのも選択できるように」(開発者)。

## 決めたこと
- **難しくないので、作る**。難易度は「数字の組み合わせ(プリセット)を切り替えるだけ」なので、新しい仕組みは小さくて済む。
- ゲームを始める前に、**メニュー画面**を出す。「やくわり」(ザリガニ / 農家さん)と「なんいど」(やさしい / ふつう / むずかしい)を選び、「スタート」を押すとラウンドが始まる。
- 難易度は **3段階**(やさしい / ふつう / むずかしい)。既定は「ふつう」。数字は `Config.Difficulties` にまとめる。
- 結果の画面に、「もう一度」(同じ設定)と「メニューへ」(選び直す)を出す。

## 選んだ案(あとで変えられる)
- **難易度は、天敵の「数字の補正」で実現した**。`Stats` に補正 `"Difficulty"` を登録し、農家さんの発見距離・気づく間・勘の確率・見失うまでの時間に、倍率をかける。季節などと同じ仕組み(仕様書 002 の拡張設計)なので、行動(`Patrol`・`Notice`・`Chase`)のコードは1行も変えていない。
  - 補正は、狙っているプレイヤーの難易度を読む。狙う相手がいない数字(勘など)は、いちばん新しく「スタート」を押した人の難易度を読む(いまは一人用なので同じ)。
  - 「気づく間」は、短くしても最低 0.4 秒を守る。「勘」の確率は 1 を超えない。
- **足し算の数字は、補正の外**で扱った。稲刈り機の「入るまでの待ち」は、倍率ではなく「足す秒数」(`HarvesterEntryDelayBonus`)なので、`Sweep` が読む(最小 0.5 秒)。ジェットのため直しは `CrayfishService` が倍率をかける。
- **点数に倍率**(`ScoreMultiplier`:0.8 / 1.0 / 1.3)。むずかしいほど高得点になる。クリアのボーナスを足したあと、最後にかけて、整数に丸める。
- **ベスト記録は、「やくわり」×「なんいど」の組み合わせごとに別々**。難易度が違う点数を、同じ記録で比べないため。保存の形は、1人1つのキーの中の表 `{ ["Crayfish_Normal"] = 数字, ... }`。これまでの記録(数字だけ)は `Crayfish_Normal` に引きつぐ(読み込んだ値が数字なら、その数字を入れる)。保存は `UpdateAsync` で、キーごとに高いほうを残す。
- **`Farmer`(農家さん)は 016 で作る**。015 では「選べる土台」だけ: `role` は `"Crayfish"` と `"Farmer"` の両方を扱え、`Config.Roles.Farmer.Ready` が `false` の間は、メニューの「スタート」が「じゅんびちゅう」になって押せない(サーバー側も、`Farmer` が来たらメニューのままにする)。【016で `true` にした】016 の担当は、`Ready` を `true` にして、`RoundService` の `startRoundForRole` を置き換える。
- **追跡の速さの上限と、稲刈り機の速さは、難易度で変えない**。
  - 追跡の速さの上限(ザリガニの 1.05 倍): 「つかまえる側が、速すぎて逃げられない」状態を、どの難易度でも作らないため(公平さ)。
  - 稲刈り機の速さ: ラウンドの中に走り切れる時間を、`GrowthStageSeconds` から決めているため。速さを変えると、走り切れなくなるおそれがある(`Config.luau` のコメント参照)。
- **メニューの状態の知らせ**は、新しい通信を増やさず、これまでの `RoundState` に `"Menu"` を足した(引数の形は同じ)。メニュー待ちの間は、サーバーが毎秒これを送り直す(クライアントの起動前に送った知らせを取りこぼさないため)。
- 画面の文言・色・大きさは `MenuController.luau` の定数。ゲーム名は `Config.GameName`。

## 作ってみて気をつけたこと
- メニューにいる間は、ラウンドが始まっていないので、稲は育たず、天敵・稲刈り機・餌は動かない。ザリガニも動けない(`WalkSpeed = 0`)。
- 「スタート」「メニューへ」は、どちらも「生まれ直し」(`LoadCharacter`)で切り替える。既存の「もう一度」と同じ流れ。
- 不正なお願い(型が違う・知らない文字・メニュー以外での「スタート」・結果の画面以外での「メニューへ」・連打)は、サーバーが黙って捨てる。

## 見直す時期
- 難易度の差が小さい・大きいと感じたら: `Config.Difficulties` の数字を調整する(調整のしかたは `docs/design/difficulty.md`)。
- 「むずかしい」が理不尽に感じたら: 「気づく間」の下限(`DifficultyNoticeFloorSeconds`)を上げる、`FarmerSightMultiplier` を下げる。
- 難易度を増やしたくなったら: `Difficulties` と `DifficultyOrder`、`DifficultyLabels` に足すだけ(コードは変えない)。
- 016(農家さんモード)ができたら: `Roles.Farmer.Ready` を `true` にして、遊んで確かめる。【016で `true` にした】

## レビュー後の調整(2026-11-03)
レビューの指摘のうち、015 に関わるものを直した。
- **「スタート」のあと、メニューから抜けられなくなるのを防いだ**(`RoundService`): 生まれ直し(`LoadCharacter`)の失敗・`Humanoid` が見つからない・「スタート」の処理のエラーのとき、フェーズを `Menu` に戻して、メニュー待ちにする(警告は1回だけ)。保険の見張りも足した: フェーズが `Playing` なのに `State` が `"Menu"` のまま `Config.StartStuckSeconds`(8秒)続いたら、メニューに戻す(毎秒の更新の中で判定。ラウンドが始まったら時計をリセット)。
- **メニュー待ちの競合**: `onCharacterAdded` で、フェーズを読む直前にも、`player.Character == character` を確かめる(待つ前・待ったあと・読む直前)。
- **稲刈り機の予告の長さ**(`GuiController`): 4秒の固定をやめ、そのプレイヤーの難易度の「入るまでの待ち」(`HarvesterEntryDelaySeconds + HarvesterEntryDelayBonus`。最小 `HarvesterEntryDelayMinSeconds`)+ `Config.HarvesterWarningExtraSeconds`(1秒)にした。難易度は Player の Attribute `Difficulty` から読む。
- **メニューの上に「潜る」「ジェット」のボタンが残らないように**(`DiveController`・`JetController`): `RoundState` が `"Menu"` の間は、操作の取り付けを外す。メニューを出たら、やくわりに合わせて、また取り付ける。
- **農家さんAIの「出現直後の猶予」**(`EnemyService`): 「スタート」が通った時点で農家さんAIが作られると、生まれ直しの間に猶予が減ってしまうので、ラウンドが始まるたびに(`RoundService.OnRoundStart`)、ザリガニのラウンドなら猶予をやり直す。
- **直書き・二重の定義**: 「5分間」の文言は `RoundSeconds` から計算。`StartRequest`・`MenuRequest` の設定は、015 のブロックに移した。`SetupService` の `FALLBACK_DIFFICULTY` をやめ、`Config.DefaultDifficulty` を使う。
- **見送り**(いまは直さない):
  - 倍率の重複した確認(`getMultiplier` 相当が4か所にある)は、まとめない。
  - `ResetRice` の二重呼び出し(`resetWorld` と `startRound`)は、直さない。
  - 気づく間の下限(`DifficultyNoticeFloorSeconds`)を、読む側に移すことは、しない。
