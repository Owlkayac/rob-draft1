# 仕様書 012: 餌を食べて点数が増える / ベスト記録

> 状態: 実装済み(開発者の確認待ち)。仕様書007の「次の質感の候補」5番。企画書(docs/game-concept.md)の「餌を食べて点数が増える」を、この仕様書で作る。
> 目的: 逃げるだけでなく、「危ないところへ取りにいく」理由と、もう一度遊びたくなる目標(ベスト記録)を作る。

## 1. 餌(エサ)
- 田んぼの中に、**餌**が、いつも決まった数(`FoodCount`=10)だけある。
- 見た目: 小さな明るい色の丸(図形で作る。`FoodColor`、`FoodSize`)。ゆっくり上下にゆれる(任意)。外部の素材は使わない。
- 置く場所: 田んぼの中の、ランダムな位置。壁から `FoodWallMargin`(10)以上はなす。同じ位置に、かさならない(`FoodMinSpacing`)。
- **食べる**: 遊んでいて、生きていて、**潜っていない**プレイヤーが、餌から `FoodEatDistance`(3.5)以内(横方向)に入ったら、食べる。食べた餌は消え、点が `FoodPoints`(10)入る。
  - 潜っている間は、食べられない。
  - 食べた餌は、`FoodRespawnSeconds`(6)秒後に、別の場所に、新しく出る(つねに、数が保たれる)。
- 判定は、サーバーで行う(0.1秒ごとなど、軽い間隔)。
- 「もう一度」で、餌は、すべて、置き直される。

## 2. 点数
- **点数** = 食べた餌の点 + 生き延びた秒数 × `ScorePerSecond`(1) + クリアのときの `ClearBonus`(100)。
- 画面の左上に、いまの点数を出す(「てん: 123」)。食べると、増える(数字が変わる)。
- つかまったときは、そこまでの点数が、そのまま、結果になる(減らない)。
- 点数の計算は、サーバーが持つ(プレイヤーごとの表。将来の複数人に備える)。
- 結果の画面に、点数と、ベスト記録を出す。
  - 「つかまった! てん: 123 / ベスト: 200」
  - 「稲刈りの日まで生き延びた! てん: 350 / ベスト更新!」(ベストを更新したときだけ、「ベスト更新!」)

## 3. ベスト記録(保存)
- プレイヤーごとの、いちばん高い点数を、**DataStore**(Robloxのデータ保存の仕組み)に、保存する。
  - 鍵(キー): `Player_` + UserId。保存するのは、**点数の数字だけ**(名前などの個人情報は、保存しない)。
  - 読み込み: プレイヤーが入ったとき。失敗したら、1秒待って、最大3回やり直す(pcall で包む)。それでも失敗したら、保存なしで遊べる(警告を出す)。
  - 保存: ベストを更新したとき(ラウンドの終わり)、プレイヤーが退出するとき(変わっていれば)、サーバーが閉じるとき(`BindToClose`)。失敗したら、やり直す(最大3回)。
  - 書き込みは、ベストを更新したときだけ(回数の上限に、触れないように)。
- Studio で、ゲームを公開していない、または、API サービスへのアクセスが、許可されていないときは、保存・読み込みが、失敗する。そのときは、そのプレイ中だけの記録(メモリ)になる。エラーで止まらない。

## 4. 通信
- 新しい RemoteEvent `ScoreState`(サーバー → クライアント): 内容は、いまの点数、ベスト記録、ベストを更新したか(boolean)、餌を食べたばかりか(boolean)。1秒に1回(Playing 中)と、餌を食べたとき・ラウンドの終わりに、送る。
- クライアントは、表示するだけ。点数の計算・保存は、すべてサーバー。

## 5. 数値(Config.luau にまとめる)
| 名前 | 初期値 | 意味 |
|---|---|---|
| FoodCount | 10 | 田んぼにある餌の数 |
| FoodPoints | 10 | 餌1つの点 |
| FoodEatDistance | 3.5 | 食べられる距離 |
| FoodRespawnSeconds | 6 | 食べたあと、次の餌が出るまでの時間 |
| FoodWallMargin | 10 | 壁から、餌を置かない距離 |
| FoodMinSpacing | 8 | 餌と餌の、最小の間隔 |
| FoodSize / FoodColor | 1.2 / 明るい橙色 | 見た目 |
| ScorePerSecond | 1 | 生き延びた1秒の点 |
| ClearBonus | 100 | クリアのボーナス |
| BestScoreStoreName | "BestScores" | DataStore の名前 |
| BestScoreRetries / BestScoreRetryWaitSeconds | 3 / 1 | 読み書きのやり直し |
| BestScoreCloseWaitStepSeconds | 0.1 | サーバーが閉じるとき、保存が終わったかを見る間隔(秒) |

## 6. 作らないこと
- ランキング(他のプレイヤーとの比較)
- 餌の種類(特別な餌、危ない餌など)
- 点数の使い道(買い物など)
- 農家さん・稲刈り機が、餌を狙うこと
- 点数による課金・有利な課金

## 7. 注意
- 餌は、農家さんや稲刈り機の通り道にも置かれる(ランダムのため)。取りにいくと、危ない。これが、ねらい。
- 将来、複数人になるとき、餌は、みんなで共有する(だれかが食べたら、みんなから消える)。点数は、プレイヤーごと。

## 8. 確認方法(Studioで遊んで確かめること)
1. 田んぼに、橙色の丸が10個ある。壁ぎわにはない。
2. 近づくと、食べて、消え、点が増える(左上の数字)。6秒後に、別の場所に出る。数は、10に保たれる。
3. 潜っている間は、食べられない。
4. 結果の画面に、点数とベストが出る。ベストを更新すると、「ベスト更新!」が出る。
5. 「もう一度」で、点数が0に戻り、餌が置き直される。
6. 公開していない Studio でも、エラーで止まらない(保存の失敗は、警告だけ)。公開して、API を許可すると、次のプレイでも、ベストが残っている。
