# 仕様書 015: スタートメニューと、難易度選択

> 状態: 実装済み(開発者の確認待ち)。開発者の依頼: 「難易度選択をしたい(難しければいらない)。天敵側をやるのも、選択してできるようにしたい」。
> この仕様書は、**メニュー画面の仕組み**と**難易度**を扱う。天敵側(農家さんをプレイする遊び方)は、仕様書016。
> 難易度は、数字の組み合わせ(プリセット)を切り替えるだけなので、難しくない(だから、作る)。

## 1. 何のための機能か
ゲームを始める前に、**やくわり**(ザリガニ / 農家さん)と**なんいど**(やさしい / ふつう / むずかしい)を、選べるようにする。

## 2. ゲームの流れ(これまでは、入ったら、すぐ始まった)
1. プレイヤーが入ると、**メニュー**が出る(ゲームは、まだ始まらない。稲は育たない。天敵は、動かない)。
2. 「やくわり」と「なんいど」を選び、「スタート」を押す。
3. ゲームが始まる(これまでと同じラウンド)。
4. つかまった・クリアしたら、結果の画面に、「もういちど」(同じ設定)と「メニューへ」が出る。
   - 「もういちど」: 同じ設定で、やり直す(これまでと同じ)。
   - 「メニューへ」: メニューに戻る(設定を、選び直せる)。

## 3. メニューの画面(クライアントが、コードで作る)
- 画面の中央に、大きなパネル。上に、ゲーム名 **ZARIGANI**。
- 「やくわり」: 2つのボタン。
  - 「ザリガニ(にげる)」
  - 「農家さん(つかまえる)」 ← 仕様書016。
- 「なんいど」: 3つのボタン。「やさしい」「ふつう」「むずかしい」。
- 選んでいるボタンは、色が変わる(はっきり分かる)。
- いまの「やくわり」と「なんいど」の組み合わせの、**ベスト記録**を、表示する。
- 大きな「スタート」ボタン。
- 説明の一行(例: ザリガニ「農家さんから、5分間、にげきれ!」、農家さん「ザリガニを、ぜんぶ つかまえろ!」)。
- ボタンは、スマホでも押しやすい大きさ。文字は、日本語。

## 4. 難易度(プリセット)
難易度は、「やくわり」ごとに、**そのプレイヤーにとっての、やさしさ**を表す(やさしい = そのやくわりで、勝ちやすい)。
数字は、`Config.Difficulties`(`Easy`、`Normal`、`Hard` の表)にまとめる。

| 項目 | やさしい | ふつう | むずかしい | 効くところ |
|---|---|---|---|---|
| FarmerSightMultiplier | 0.8 | 1.0 | 1.2 | 農家さんの、見つける距離(ザリガニで遊ぶとき) |
| FarmerNoticeMultiplier | 1.4 | 1.0 | 0.8 | 気づく間の長さ(最低0.4秒は保つ) |
| FarmerHunchMultiplier | 0.4 | 1.0 | 1.6 | 「勘」の確率(1を超えない) |
| FarmerLoseSightMultiplier | 0.7 | 1.0 | 1.4 | 見失うまでの時間(追跡が、しつこいか) |
| HarvesterEntryDelayBonus | +1.5 | 0 | -1.0 | 稲刈り機の予告(秒) |
| JetCooldownMultiplier | 0.75 | 1.0 | 1.3 | ジェットのため直し(ザリガニで遊ぶとき) |
| ScoreMultiplier | 0.8 | 1.0 | 1.3 | 点数の倍率(むずかしいほど、高い) |
| PreyCount | 2 | 3 | 5 | AIザリガニの数(農家さんで遊ぶとき) |
| PreySpeedMultiplier | 0.9 | 1.0 | 1.1 | AIザリガニの速さ |
| PreyAwarenessMultiplier | 0.8 | 1.0 | 1.2 | AIザリガニが、農家さんに気づく距離 |
- 農家さんの追跡の速さの上限(ザリガニの1.05倍)は、難易度で変えない(公平さのため)。
- 稲刈り機の速さは、難易度で変えない(ラウンド内に走り切るため)。
- 既定は「ふつう」。

## 5. 実装の方針
- **新しい部品 `SetupService`(サーバー)**: プレイヤーごとの「フェーズ」(`Menu` / `Playing`)、選んだ「やくわり」「なんいど」を、`Player` をキーにした表で持つ。
  - 通信: 新しい RemoteEvent `StartRequest`(クライアント → サーバー。`role: string`、`difficulty: string`)、`MenuRequest`(クライアント → サーバー。値なし)。サーバーは、値の型・許される文字列(`"Crayfish"` / `"Farmer"`、`"Easy"` / `"Normal"` / `"Hard"`)・送信者のフェーズ・受け付け間隔を、検証する。
  - プレイヤーが入ったとき、フェーズは `Menu`。キャラクターは、スタート地点に生まれるが、動けない(`WalkSpeed=0`)。
  - `StartRequest` が通ったら、やくわりと難易度を保存し、フェーズを `Playing` にして、ラウンドを始める。
  - `MenuRequest`(結果の画面の「メニューへ」)が通ったら、フェーズを `Menu` に戻す。
- **RoundService**: これまでは、キャラクターが生まれたら、すぐラウンドを始めた。これを、フェーズが `Playing` のときだけ始めるようにする。`Menu` のときは、動けない状態で待つ。
  - `RoundState` の状態に、新しく `"Menu"` を足す(送る引数の形は、変えない)。ほかの画面(GuiController、LightingController、SoundController)は、`"Menu"` を、安全に扱う(朝の光、環境音は鳴らさない、残り時間は出さない)。
- **難易度の反映**: 天敵の数字は、`Stats` の補正(`RegisterModifier`)として、`"Difficulty"` を登録する(季節などと同じ仕組み。仕様書002の拡張設計)。補正の関数が、そのときの難易度を、`SetupService` から読む(狙っているプレイヤーの難易度。なければ、いちばん新しく始めたプレイヤーの難易度)。
- **ベスト記録(仕様書012)**: 「やくわり」と「なんいど」の組み合わせごとに、別々に記録する(`ScoreService`)。保存の形は、1人1つのキーの中の、表(`{ ["Crayfish_Normal"] = 数字, ... }`)にする。これまでの記録(数字だけ)は、`Crayfish_Normal` として、引きつぐ(読み込んだ値が、数字なら、その数字を `Crayfish_Normal` に入れる)。点数は、`ScoreMultiplier` を掛けて、整数に丸める。
- **メニューの画面(クライアント `MenuController`)**: `RoundState` が `"Menu"` のとき、メニューを出す。「スタート」で `StartRequest` を送る。ベスト記録は、サーバーが、読み込み後と更新後に、新しい RemoteEvent `BestScores`(サーバー → クライアント。表)で、送る。
- **結果の画面(GuiController)**: 「もういちど」の横に、「メニューへ」を足す。

## 6. 数値(Config.luau にまとめる)
`Difficulties`(表)、`DefaultRole="Crayfish"`、`DefaultDifficulty="Normal"`、`StartRequestMinInterval`(1)、メニューの画面の文言・色(MenuController 内の定数でよい)。

## 7. 作らないこと
- 難易度の、自由な数字入力
- 途中での、難易度の変更(メニューに戻って、選び直す)
- 難易度ごとの、別の舞台(田んぼ)
- ランキング

## 8. 確認方法(Studioで遊んで確かめること)
1. ゲームを始めると、メニューが出る。まだ、稲は育たず、天敵は動かない。
2. 「やくわり」と「なんいど」を選んで、「スタート」を押すと、ゲームが始まる。
3. つかまる・クリアすると、「もういちど」と「メニューへ」が出る。「もういちど」で、同じ設定で、やり直す。「メニューへ」で、メニューに戻る。
4. 「やさしい」は、農家さんが、見つけにくく、気づくのが遅い。「むずかしい」は、その逆。点数は、むずかしいほど、高い。
5. ベスト記録が、「やくわり」と「なんいど」の組み合わせごとに、別々に出る。
6. メニューにいる間に、エラーが出ない。ほかの画面(残り時間、光、音)が、おかしくならない。
